# UI

UI entities are ordinary `VSE_Entity`s. What makes one "UI" is carrying a `VSE_RectTransform`:
it is laid out in its window's own coordinates, drawn after the world, and scaled by its parents.

There is no widget type enum. An entity is clickable because it has a `VSE_Interactable`, and it
shows text because it has a `VSE_DynamicText` — so adding a new kind of widget is a new component,
not a new case in two switch statements.

## Buttons

`VSE_ButtonDesc` is zero-initialised, so set only what you care about:

```c
VSE_Entity *play = VSE_CreateButton(engine, &(VSE_ButtonDesc){
    .window    = menuWindow,
    .position  = menuWindow->windowCenterPoint,
    .scale     = {2, 2},
    .texture   = VSE_LoadTexture("Button.png"),
    .text      = "Play",
    .textColor = (SDL_Color){0, 0, 0},
    .userData  = game,
    .OnClick   = OnPlayClicked,
    .OnHover   = OnHover,
    .OnHoverExit = OnHoverExit,
});
```

Leave `texture` out and a solid rect is built from `size` and `backgroundColor` instead. Leave
`material` out for the default shader pair, `scale` out for `{1,1}`, `textScale` out for
`{0.2f, 0.2f}`, and `text` out for a button with no label.

The handler receives whatever you put in `userData`:

```c
static void OnPlayClicked(VSE_Engine *engine, void *userData)
{
    GameContext *game = userData;
    game->pendingState = GAMEPLAY;
}
```

Hover callbacks receive the entity, so reach state through `button->userData` (which
`VSE_CreateButton` sets to `desc->userData` for you) or through a component.

## Text

**Static text** rasterises once into a texture — sharp, but fixed:

```c
VSE_CreateStaticText(engine, window, "You Win", (SDL_Color){255, 255, 255},
                     window->windowCenterPoint, (VSE_Vector2Float){0.3f, 0.3f}, NULL);
```

**Dynamic text** draws from the glyph atlas every frame, so the string can change. The buffer is
**borrowed, not copied** — it must outlive the entity:

```c
static char scoreText[32];
VSE_CreateDynamicText(engine, window, scoreText, position, VSE_VECTOR2_FLOAT_ONE, NULL);
/* later, from anywhere */
snprintf(scoreText, sizeof(scoreText), "Score: %d", score);
```

## Input fields

```c
VSE_Entity *field = VSE_CreateInputField(engine, &(VSE_InputFieldDesc){
    .window    = window,
    .position  = position,
    .scale     = {2, 2},
    .texture   = VSE_LoadTexture("Field.png"),
    .maxLength = 16,
});

VSE_InputField *text = VSE_GetComponent(field, VSE_COMPONENT_INPUT_FIELD);
printf("%s\n", text->text);
```

Click to focus, Backspace deletes, Escape releases. `maxLength` defaults to 10.

## Parenting and scale

`VSE_RectTransform` holds the parent link, the child list, and `parentScale` — the product of every
ancestor's scale, maintained by the UI system each frame.

```c
typedef struct VSE_RectTransform {
    VSE_Vector2Float parentScale;
    VSE_Vector2Float lastPosition;
    VSE_Entity      *parent;
    VSE_List        *children;
} VSE_RectTransform;
```

A button parents its own label, which is why moving or scaling a button carries its text along.

**To animate a button's size, tween its `parentScale`, not `transform.scale`.** Its own scale is a
fixed authored value; `parentScale` is the multiplier the label inherits, so tweening it grows the
button and the label together:

```c
static void OnHover(VSE_Engine *engine, VSE_Entity *button)
{
    VSE_RectTransform *rect = VSE_GetComponent(button, VSE_COMPONENT_RECT_TRANSFORM);
    VSE_TweenData d = { .vector2FloatTween = { .fromValue = {1, 1}, .endValue = {1.5f, 1.5f} } };
    VSE_PlayTween(engine, VSE_CreateTween(VSE_VECTOR2_FLOAT_TWEEN, &rect->parentScale,
                                          d, 0.5f, true, VSE_OUT_QUINT));
}
```

## Building a widget by hand

The creation helpers are conveniences. Nothing stops you assembling one yourself, which is the point
of the component model:

```c
VSE_Entity *e = VSE_CreateUIEntity(engine, window, position, scale, NULL);

VSE_AddComponent(e, VSE_COMPONENT_SPRITE_RENDERER, &(VSE_SpriteRenderer){
    .texture = tex, .material = mat,
    .originalSize = {tex->width, tex->height} });

VSE_AddComponent(e, VSE_COMPONENT_INTERACTABLE, &(VSE_Interactable){
    .data = game, .OnClick = OnClicked });
```

A toggle, a slider or a dropdown is a component of your own plus a behaviour — no engine change.

## Hit testing

Hover and clicks are tested against the drawn size on the entity's `VSE_SpriteRenderer`, using mouse
coordinates in the **focused window** only. An entity needs both a `VSE_Interactable` and a sprite to
be clickable — there is nothing to hit otherwise.

## Gizmos

With `debugMode` on, buttons and input fields get a red outline labelled with their position and
size. Attach one to anything with `VSE_CreateGizmo(engine, window, colour, thickness, entity)`.
